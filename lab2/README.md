## Цель и задание

Приобрести практические навыки управления процессами в операционной системе и организации обмена данными между процессами через неименованные каналы (`pipe`).

По варианту № 17 родительский процесс создаёт **два дочерних процесса**. Первые две строки, введённые пользователем, задают имена выходных файлов. Следующие строки произвольной длины родитель распределяет по каналам:

- строки длиной **не больше 10 символов** направляются в `pipe1` процессу `child1`;
- строки длиной **больше 10 символов** направляются в `pipe2` процессу `child2`.

Оба дочерних процесса удаляют гласные буквы из поступивших строк и записывают результат в соответствующие выходные файлы.

**Среда выполнения:** Windows 11, WSL (Linux). **Язык:** C11. **Системный интерфейс:** POSIX/Linux. **Сборка:** CMake, GCC 13.3.0.

## Реализация

Используются две отдельные программы, причём один исполняемый файл `child` запускается дважды:

- **`parent`** — читает имена файлов и строки пользователя, создаёт два канала и два дочерних процесса, определяет длину строки и передаёт её соответствующему ребёнку; после EOF закрывает пишущие концы каналов и ожидает завершения детей.
- **`child`** — читает строки из перенаправленного `stdin`, удаляет латинские гласные `a`, `e`, `i`, `o`, `u`, `y` (в обоих регистрах) и записывает результат в перенаправленный `stdout`.

Схема передачи данных:

```text
                               parent
                           ввод пользователя
                                  │
                       подсчёт длины UTF-8
                       ┌──────────┴──────────┐
                       │                     │
                   ≤ 10 символов         > 10 символов
                       │                     │
                     pipe1                 pipe2
                       │                     │
                      stdin                 stdin
                       │                     │
                     child1                child2
                       │                     │
                  удаление гласных     удаление гласных
                       │                     │
                      stdout                stdout
                       │                     │
                    short.txt             long.txt
```

Каналы создаются вызовом `pipe()` **до** создания детей через `fork()`, поэтому их дескрипторы наследуются дочерними процессами. В каждом ребёнке `dup2()` связывает стандартный ввод (`fd = 0`) с читающим концом нужного канала, а стандартный вывод (`fd = 1`) — с открытым на запись файлом. Затем `execl()` заменяет образ процесса программой `./build/child`; PID при этом сохраняется.

Стороны закрывают ненужные дескрипторы. После завершения ввода родитель закрывает оба конца записи: дочерние процессы дочитывают данные, получают EOF, сбрасывают буферы и завершаются. Родитель получает их статусы через `waitpid()`.

Основные используемые интерфейсы:

| Функция / механизм | Назначение |
| --- | --- |
| `pipe()` | Создание двух неименованных каналов |
| `fork()` | Создание дочерних процессов |
| `dup2()` | Перенаправление `stdin` и `stdout` |
| `open()` | Открытие или создание выходного файла (`O_WRONLY`, `O_CREAT`, `O_TRUNC`) |
| `execl()` | Запуск программы `child` в уже созданном процессе |
| `getline()` | Чтение строк с динамически расширяемым буфером |
| `write()` | Передача байтов через канал; повторная запись при частичном выполнении |
| `close()` | Закрытие лишних концов каналов и других дескрипторов |
| `signal(SIGPIPE, SIG_IGN)` | Возможность обработать `EPIPE` вместо завершения родителя сигналом |
| `waitpid()` | Ожидание детей и получение статусов завершения |
| `perror()`, `errno`, `ferror()` | Диагностика ошибок системных и буферизованных операций |

Длина строки для маршрутизации определяется по **кодовым точкам корректной UTF-8 строки**, без завершающих `\r` и `\n`. Переводы строк при передаче сохраняются. Пустая строка относится к `child1` и остаётся пустой строкой в выходном файле.

**Ограничение реализации:** функция удаления гласных обрабатывает только латинский алфавит; русские гласные остаются без изменений. Подсчёт символов предполагает корректный UTF-8 и не выполняет полной проверки его валидности.

## Сборка и запуск

Команды выполняются **в терминале WSL из корня** `~/projects/os_labs/lab2_variant17`:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/parent
```

CMake создаёт два исполняемых файла: `build/parent` и `build/child`. Путь к дочерней программе в исходном коде задан как `./build/child`, поэтому запускать `parent` необходимо **из корня проекта**.

После запуска ввести два имени файлов, затем строки для обработки. Для окончания ввода нажать **Ctrl+D на пустой строке** (EOF). В WSL применяется Ctrl+D, а не Ctrl+Z, как в Windows-консоли.

## Контрольный запуск

Для воспроизведения основного сценария можно использовать одну команду:

```bash
printf '%s\n' \
  short.txt \
  long.txt \
  hello \
  abcdefghij \
  abcdefghijk \
  AEIOUY \
  '' \
  Привет \
  watermelons \
  rhythm | ./build/parent
```

Вывод после обработки:

```bash
nl -ba short.txt
nl -ba long.txt
```

Ожидаемое содержимое **`short.txt`** (`child1`, длина ≤ 10):

```text
1  hll
2  bcdfghj
3
4
5  Привет
6  rhthm
```

Ожидаемое содержимое **`long.txt`** (`child2`, длина > 10):

```text
1  bcdfghjk
2  wtrmlns
```

Строка `abcdefghij` длиной ровно 10 символов направляется первому ребёнку, а `abcdefghijk` длиной 11 — второму. `AEIOUY` превращается в пустую строку. Кириллическая строка `Привет` используется для проверки подсчёта UTF-8-символов, а не удаления русских гласных.

При успешном завершении `parent` возвращает нулевой код. PID детей выводятся в `stderr` и при каждом запуске могут отличаться.

## Проверка обработки ошибок

**Одинаковые имена выходных файлов:**

```bash
printf 'same.txt\nsame.txt\n' | ./build/parent
```

Ожидаемое сообщение:

```text
Different files are needed for the processes
```

**Невозможность открыть выходной файл:**

```bash
printf '/dev/null/output.txt\nvalid.txt\n' | ./build/parent
```

`/dev/null` не является каталогом, поэтому первый ребёнок сообщает `open output: Not a directory` и завершается с ошибкой. Родитель получает его статус через `waitpid()` и выводит `child1 exited with code 1`. Сообщения могут появиться в разном порядке из-за независимого планирования процессов.

При попытке отправить данные уже завершившемуся ребёнку возможна ошибка `write pipe: Broken pipe` (`EPIPE`). Игнорирование `SIGPIPE` позволяет родителю обработать её без аварийного завершения по умолчанию.

## Диагностика процессов и системных вызовов

Для работы внутри WSL используются **`ps`**, виртуальная файловая система **`/proc`** и **`strace`** (вместо Windows Process Monitor).

### 1. Дерево процессов

В одном терминале запустить `./build/parent`, ввести `short.txt` и `long.txt`, но пока не завершать ввод. Во втором терминале выполнить:

```bash
ps -o pid,ppid,stat,cmd --forest -C parent -C child
```

В эксперименте были зафиксированы родитель **PID 21476** и дети **PID 21546** и **21547**. Для обоих детей `PPID = 21476`, что подтверждает их происхождение от одного родителя. Значения PID относятся только к данному запуску.

### 2. Файловые дескрипторы

Подставить актуальные PID детей (здесь приведены PID из сохранённого опыта):

```bash
PID1=21546
PID2=21547
ls -l "/proc/$PID1/fd"
ls -l "/proc/$PID2/fd"
```

В проведённом опыте у `child1` дескриптор `0` указывал на `pipe:[322230]`, дескриптор `1` — на `short.txt`; у `child2` соответственно `pipe:[322231]` и `long.txt`. Дескриптор `2` у обоих был связан с терминалом `/dev/pts/7`. Это подтверждает перенаправление потоков через `dup2()`.

### 3. Трассировка strace

```bash
strace -ff -o trace -e trace=process,desc ./build/parent
```

После ввода данных и завершения по EOF посмотреть трассировки:

```bash
ls -l trace.*
grep -HE 'pipe2?\(|clone3?\(|dup2\(|execve\(|openat\(|wait4\(' trace.*
grep -HE 'read\(|write\(|close\(' trace.* | tail -n 40
```

В одном из запусков `strace` зарегистрированы `pipe2([3, 4], 0)` и `pipe2([5, 6], 0)`, создание процессов **22544** и **22545** через `clone`, перенаправления `dup2`, запуск `./build/child` через `execve` и успешные `wait4` для обоих детей. Среди операций обмена были видны передача `"hello\n"` по каналу, чтение ребёнком и запись `"hll\n"` в файл. `read(...)=0` после закрытия пишущих концов соответствует EOF.

На Linux вызовы стандартной библиотеки не всегда отображаются в трассировке под теми же именами: например, `fork()` может соответствовать `clone`, `open()` — `openat`, а `waitpid()` — `wait4`.

## Основные результаты

- Родитель создаёт **два дочерних процесса**, которые выполняют одну программу `child` независимо друг от друга.
- Данные распределяются по двум каналам в зависимости от длины строки; проверены граничные значения **10 и 11 символов**, пустые строки и ввод UTF-8.
- Дочерние процессы удаляют латинские гласные и записывают результаты в разные файлы через перенаправленный `stdout`.
- После EOF родитель закрывает каналы, ожидает обоих детей и анализирует коды их завершения.
- Подтверждены обработка ошибок одинаковых имён файлов и невозможности открыть выходной файл.
- С помощью `ps`, `/proc/<PID>/fd` и `strace` подтверждены структура процессов, перенаправление дескрипторов и основные системные вызовы.
